# 整洁代码与重构

本文件是 dev-habits 门禁域之一（T2 硬性）。条款身份为方括号短名，引用约定见 SKILL.md 导语；与 SKILL.md 冲突按仲裁阶梯裁决。项目自身约定优先。写或改非琐碎函数、决定新类型/常量/模块的归属，或重构既有代码前必读。内容蒸馏自 Martin Fowler《重构：改善既有代码的设计》的代码味道目录、Robert C. Martin《代码整洁之道》与 Michael Feathers《修改代码的艺术》，只保留 Go、Rust、TS 后端语境适用的部分；OOP 向味道（继承滥用、Middle Man）不搬。

## 结构与命名（写代码时）

- **[函数只做一件事]** 一个函数只做一个抽象层级上的事：参数解析、业务规则、IO、格式化不混在同一函数。理想 20 行内，含错误处理的 Go、Rust 函数以约 50 行为拆分提醒上限；是否该拆以本条为准——判定标准：能整体提出来命名成函数的段落，就该提，写法对齐『文件规模提醒』。
- **[文件自顶向下]** 文件自顶向下读成一篇叙事：高层意图函数在前、细节在后，调用者紧邻被调用者；强关联代码物理相邻，隔了半屏还要互相理解的"垂直距离"就是要搬家的信号。
- **[嵌套限深]** 控制流嵌套（if/for/match/闭包）不超过 2 层，第 3 层出现就是信号：用提前返回消解，Go 与 Rust 的错误路径一律 early return（Rust 优先 `?`），禁用深层 else 分支。
- **[条件提成谓词]** 组合布尔条件超过三个操作数或需要注释才能读懂时，提成具名谓词函数或具名布尔变量（isEligible、hasPendingOrder），条件读出来就是业务规则；取反嵌套的德摩根展开不如直接具名。
- **[重复分支收敛]** 同一个维度（类型码、状态、命令字）的 switch 或 match 在多处出现，改一个分支要改多处就是霰弹式修改的分支版：收敛到一处——查表、枚举带方法或集中的分派函数；多态只在变体真实存在且持续增殖时用，不为消 switch 造继承。
- **[参数收敛]** 参数以 3 个为提醒上限；boolean 参数当模式开关用的拆成两个具名函数；同一组参数结伴出现两次以上（参数泥团）收敛成 struct 或对象；禁输出参数，结果一律用返回值承载。
- **[命令查询分离]** 查询函数无副作用：读操作不悄悄写库、发消息、改缓存、记指标；有副作用的函数名必须明示（save、send、invalidate），不让调用方踩隐藏状态。函数也不暗中改写传入参数与全局状态——承诺只做名字说的那件事。
- **[可变不外泄]** 模块不暴露可变内部状态：Go 禁包级可变变量当全局状态用、导出函数不把内部 slice 或 map 的引用递给调用方改；TS 共享对象默认不原地改，要改就返回新值；全局可变数据（global data）是最重的味道，出现即修。并发下的共享另按『共享状态最小』。
- **[错误路径不遮蔽主流程]** 错误处理抽小或提前返回，正常路径保持自顶向下线性；禁把 try、match、if err 包住整个函数体、把主逻辑挤成一坨。错误的包装与链路语义另按『错误处理按项目约定』。
- **[命名见名知义]** 一个概念全库只用一个词（account 与 user 不得混指同一物）；函数名动词短语、布尔值 is 或 has 前缀；读不懂的名字先改名再动结构——重构的第一步永远是 rename。禁空泛后缀文件（Util、Helper、Manager、Common、Shared、Misc、Data、Info）收编杂物：放进去之前每个成员先问准确归属，宁可建准确命名的模块。命名不撒谎：不是 List 别叫 accountList（就叫 accounts）；禁 a1、a2 与 ProductInfo、ProductData 式无意义区分；除短循环下标外不用单字母名，名字要能一搜即中全部用途。
- **[新代码归位]** 新函数、类型、常量按既有分层与目录归属放置（『分层按业务域』『基础设施单向依赖』）；类型定义放在类型所属模块，不在使用处旁边内联定义；找不到明确归属先问，不就近堆在当前文件末尾。
- **[构造与使用分离]** 重量级依赖（HTTP 客户端、连接池、文件句柄、时钟）不在业务函数体内构造，由上层装配传入；测试因此才注入得了 fake，见『外部依赖 mock』。轻量纯构造（临时 buffer、局部配置对象）不受此限。
- **[第三方边界收口]** 第三方与框架的类型、错误、异常不许越过适配层：orm、reqwest、axios 的错误在边界翻译成本领域错误（语义对齐『错误响应统一格式』）；vendor 特有的配置与怪癖封在 adapter 内，业务代码只认自己的类型。
- **[变化聚拢]** 结构按变化方向组织：一个模块因多种无关原因被反复改（发散式变化）就按原因拆；一个功能改动总要散落多处文件（霰弹式修改）就把相关知识收敛到一处。
- **[内聚分群即拆]** 内聚的判定信号：模块内函数明显分成只用这几块数据、只用那几块数据的两群，分群线就是拆分线；数据和用它的函数放一起，无关的别留在同一模块。
- **[依赖无环]** 模块依赖必须是有向无环图：Go 包循环与 Rust 模块循环编译器直接拒绝，禁用接口或别名中转绕环；TS 循环依赖真实存在，选配 import/no-cycle 钉死（配置见 templates/ts/eslint.config.mjs 注释段）。出现环说明边界划错，先拆共享层而不是绕。
- **[领域类型替代裸原语]** 同一语义的 ID、状态码、金额、单位裸用 string 或 int 到处传（基本类型偏执）时定义领域类型：Rust newtype、Go 定义类型加方法、TS branded type；类型即文档，参数错位编译期就报。
- **[数据对象分治]** 纯数据（传输模型、持久化模型、配置）就让它透明：字段公开、不带行为、不包一层纯转发的访问器；带不变式或行为的类型把状态藏起来只暴露方法。最糟的是两头都占：字段裸奔再补一层转发方法——既没有封装的保护也没有数据结构的简单。
- **[依恋即搬家]** 函数主要在读写另一个模块的数据（依恋情绪）时，把函数搬过去；只对别人的数据做计算的逻辑不属于当前模块。
- **[禁深链取数]** `a.b().c().d()` 式调用链（TS 的 `?.` 链同理）超过两跳，在中间对象上补一个表达意图的方法收敛，不一路点到底。

## 重构纪律（改代码时）

- **[触碰即净]** 本次触碰的函数，交付时比进来时干净：顺手改名、删死代码、提谓词、消重复，每一处独立成步且与功能改动分开提交；清理范围以本次 diff 触碰的函数为限，文件其余部分与范围外按『死代码上报』。童子军规则的边界由本条划定，与『范围最小化』的例外在 SKILL.md 对齐。
- **[重构行为保持]** 重构的定义是不改变可观测行为的结构调整：结构调整与行为变更分开提交，纯重构不动测试断言；禁把功能、数据迁移伪装成"清理"夹带。两顶帽子原则：要么戴加功能的帽子，要么戴重构的帽子，绝不同时戴。
- **[重构让路]** 功能被烂结构挡住时，先做一次最小的"让路重构"让功能变容易，单独提交，再实现功能；功能落地后清掉这次实现新产生的债。让路重构只修挡路的，范围之外的旧债仍按『死代码上报』处理。
- **[重构先有安全网]** 动结构前目标区域必须有测试兜底；无测试的既有代码先写特征测试钉住当前行为（连同看起来怪的行为一起钉），绿了再动——与『修 bug 先写复现测试』同一条安全网思路。
- **[重构小步走]** 每一步是可构建、测试绿的最小变换：rename、提取、内联、搬家、加提前返回，绿了再走下一步；想整个重写时，把冲动换成"下一个最小的行为保持变换"。在测不动的旧代码里加逻辑，优先另起一个可测的新函数让旧代码调用，不在烂摊子里继续堆行。
- **[重构有停点]** 只处理挡住当前改动的味道，修到改动容易做为止，不扩大成顺手清理全文件——触碰范围内的最小清理按『触碰即净』执行；范围外的味道按『死代码上报』处理：指出、问、不动。为拆依赖引出的临时接缝（过渡包装、测试专用后门）当场收尾，不留永久疤痕。
