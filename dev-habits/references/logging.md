# 日志与排查

本文件是 dev-habits 门禁域之一（T2 硬性）。条款身份为方括号短名，引用约定见 SKILL.md 导语；与 SKILL.md 冲突按仲裁阶梯裁决。项目自身约定优先。写日志或排查问题前必读。

- **[日志为排查服务]** 日志为排查服务：写关键路径时默认"出问题只能靠日志还原现场"——外部调用（HTTP/RPC/DB/缓存/队列/第三方 API）记目标、关键入参、耗时与结果；关键分支与决策点（降级、重试、fallback、限流与规则命中）记走了哪条路及依据；状态变更类写操作（创建/更新/删除）记操作主体、对象与关键结果；后台与异步任务（定时任务、消费者、goroutine/task）记开始、结束、耗时与失败原因。失败路径必须有日志且带上下文（错误本身加关键 ID/参数），禁止只有一句 "failed" 而看不出是谁、对什么、失败在哪一步。
- **[日志级别语义固定]** 日志级别按固定语义选用，跨项目通用：error=本应成功但失败、需要人介入排查（请求处理失败、任务失败、数据写入失败）；warn=不符合预期但已自动处理或降级、值得留意（重试后成功、降级兜底、跳过脏数据、用量接近阈值）；info=关键业务动作与流程节点的常规留痕（服务启停、任务开始与结束、外部调用概要、状态变更）；debug=排查所需的详细中间状态（完整出入参、分支判定依据），生产默认关闭。禁拿 error 打可自愈的事，禁把失败只记成 info/debug。
- **[错误日志只打一次]** 错误日志只打一次：在错误最终处理处（暴露给调用方或顶层兜底处）带完整上下文记录；中间层只包装错误不重复打印；已向上返回的错误不再由当前层打 error，禁同一错误层层刷屏。
- **[结构化与脱敏]** 日志用结构化字段不拼字符串，key 风格与传输契约一致（见 [api-contract.md](api-contract.md)『传输字段 camelCase』）；敏感信息（密钥、token、密码、证件号）不落日志，必须输出时脱敏。调试残留（console.log、println!、dbg!、fmt.Println、print）按『调试残留清零』处理。
- **[排查三板斧]** 先读完整报错——堆栈与错误链逐层读完，不凭最后一行猜；复现先收敛到最小复现路径；定位按"读日志、加临时日志或断点、二分缩小范围"推进，找到机制性根因再修，见『机制根治不打补丁』。
- **[可观测三要素]** traceId 贯穿请求链，并在日志与错误响应中携带（见 [api-contract.md](api-contract.md)『错误响应统一格式』）；关键业务动作有计数与耗时指标；服务暴露健康检查与就绪探针。三者缺一不可靠日志硬扛。
