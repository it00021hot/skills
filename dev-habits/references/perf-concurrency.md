# 性能与并发

本文件是 dev-habits 门禁域之一（T2 硬性）。条款身份为方括号短名，引用约定见 SKILL.md 导语；与 SKILL.md 冲突按仲裁阶梯裁决。项目自身约定优先。做性能优化，或写并发、异步代码前必读。

- **[先测量后优化]** 性能改动先测量（pprof、explain、benchmark）拿到数字再动手；无测量的优化按未验证处理，交付时必须附前后对比数字。
- **[禁拍脑袋加缓存]** 禁无测量、无失效策略、无容量上限的"加个缓存"；缓存是显式设计：键、失效、容量、并发击穿处理写清楚，设计边界见『禁无依据兜底』。
- **[并发任务有主]** 每个 goroutine、async task 有明确所有者：启动、取消、结束可观测；context 或 cancellation 贯通传递，禁失控后台任务与泄漏。
- **[锁粒度最小]** 锁只包住临界区，禁在锁内做 IO 或调用外部；Rust 禁在 async 上下文里 block；锁顺序固定，防死锁。
- **[共享状态最小]** 共享状态最小化，优先消息传递；能不共享就不共享，必须共享时把可变性与所有者写清楚。
